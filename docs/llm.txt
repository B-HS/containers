================================================================================
CONTAINERS — AI-READY PROJECT REFERENCE
================================================================================
Self-hosted Docker management panel. A single web UI to control Docker
containers, deploy workloads behind Nginx, view traffic analytics, and manage
backups — hardened like a production control plane.

Monorepo: Bun workspace (`apps/*`, `packages/*`).
Runtime: Bun 1.3.14, TypeScript strict, all dependencies exact-pinned.
Run: `docker compose build && docker compose up -d --wait` then http://127.0.0.1:8080

1. ARCHITECTURE
================================================================================
5 containers via docker-compose. All internal services authenticate to each
other with HMAC-SHA256 shared secrets (nonce + timestamp, 30s skew). Docker
Engine API is accessed ONLY through the engine-agent.

  Browser ──► nginx (127.0.0.1:8080, edge) ──► web (Next.js, :3000)
      │            │  /api/* ──► api (:3001)
      │            └  /status (stub_status)
      └── nginx.conf managed by engine-agent via /v1/nginx/config/apply

  api (:3001) ──► engine-agent (:3002, HMAC) ──► Docker Engine (socket)
             └─► traffic-worker (:3003, HMAC)

Networks (docker):
  control   internal:true  — api, engine-agent, traffic-worker, nginx
  ingress   internal:true  — web, nginx, api
  probe     internal:true  — engine-agent + deployment staging (healthcheck)
  edge      (default)      — user workloads (non-internal, internet egress)

Volumes:
  agent-credentials, artifacts, backups, control-data, nginx-config,
  nginx-logs, registry-credentials, traffic-credentials, traffic-data

Secrets are file-backed (mode 0600), auto-generated on first boot, mounted at
/credentials, /traffic-credentials, /registry-credentials, /data. No .env.

Key source layout:
  apps/api/            Hono control-plane: auth, RBAC, jobs, backups, uploads,
                       deployments, nginx routes, notifications, audit
  apps/engine-agent/   Docker Engine client: containers, exec, streams, stats,
                       image pull/load, nginx config apply, registry creds
  apps/traffic-worker/ Access-log ingestion, analytics aggregation, export
  apps/web/            Next.js App Router panel (ko/en/ja)
  packages/contracts/  Shared Zod schemas (single source of DTO truth)
  packages/db-schema/  Drizzle schema + SQLite migrations
  packages/nginx-config/ nginx tokenizer/serializer shared by web GUI editor and
                       engine-agent protected-contract validation (single parser)
  packages/config/     env parsing (Zod) + secret loading


================================================================================
2. SERVICE / PROCESS MAP
================================================================================
api            Port 3001 (internal). Compose: apps/api/src/server.ts →
               createApp (apps/api/src/compose/create-app.ts) mounts all routes.
engine-agent   Port 3002 (internal). Docker socket owner. Routes under /v1/*
               HMAC-guarded; /ws/exec/* is ticket-gated (not HMAC).
traffic-worker Port 3003 (internal). Reads nginx access.log JSONL, ingests to
               traffic.sqlite, serves analytics.
web            Port 3000 (internal). Next.js SSR + client, proxied by nginx.
nginx          Port 8080/8081. Edge reverse proxy; 8081 is stub_status.

Internal auth (packages/contracts/src/internal-auth.ts):
  Header X-Internal-Timestamp (ms) + X-Internal-Nonce (uuid) +
  X-Internal-Signature = HMAC-SHA256(secret, `${method}\n${path}\n${timestamp}\n${nonce}\n${body}`).
  Nonce dedup + timestamp skew <= 30s. Secrets differ per link (api↔agent,
  api↔traffic) in separate volume files.

4. AUTH & AUTHORIZATION
================================================================================
Auth: Better Auth email+password. Public sign-up disabled (404). Session cookie.
  Login rate limit: nginx `containers_auth_rate` 5r/m burst=5 per $remote_addr
  + app-level 10/min per X-Real-IP (in-memory, 10k-pruned).
  Disabled account → generic 401 INVALID_EMAIL_OR_PASSWORD (no enumeration).

Roles: owner > admin > operator > viewer/auditor (auditor = read-only).
  owner immutable, cannot self-modify. Roles assigned via invitations.

Recent-auth (step-up): all DESTRUCTIVE writes require a session <= 15 min old
  (`requireRecentRole(headers, roles, 15*60*1000)`). Long-lived sessions that
  pass 15 min get 401 RECENT_AUTH_REQUIRED → re-login. Enforced on:
  container create/action/exec/remove, image pull/tag/remove, network/volume
  create+remove, prune, registry-credential CRUD, deployment manifest/release/
  secret write, backup write/restore, api-key create/revoke, user update,
  invitation create, nginx route/config, job cancel, maintenance toggle,
  exec-ticket.

Encryption keyring: deployment secret / notification webhook master keys live in
  /data/<name>-secret-key (v1) plus .v2/.v3 ... (0600). Writes use the active
  (highest) version; reads use the row's key_version column. Rotation is an
  owner-only durable job (secret.rotate) that appends a version and re-encrypts
  every row; old versions are kept so a partial rotation still decrypts.
  Backups seal every key version in secrets.enc under the operator passphrase.

API keys: `ctk_` + 32-byte random; only SHA-256 stored; scopes deny-by-default.
  Owner-only scopes (backup:write, secret:write) are enforced twice: at issue time
  (owner + recent) and at use time (the issuer's current role must still be owner),
  so keys issued before the policy or held by a demoted account stop working.
  authenticate() inner-joins user_role and rejects if disabledAt set or revoked.
  Disabling/demoting a user revokes their api keys + deletes sessions in one txn.
  Scopes: artifact:read, artifact:upload, backup:read, backup:write,
          control-plane:read, deployment:read, deployment:write, engine:read,
          image:load, job:read, job:write, secret:read, secret:write.
  Per-key rate limit 120/min (in-memory).

Management-plane boundary (engine-agent): resources labeled
  com.docker.compose.project=containers OR managed-by=containers-control-plane
  are protected from user exec/actions/logs/stats/remove/prune. User-created
  containers cannot carry these labels (schema refine rejects them).

8. NGINX & RATE LIMITING
================================================================================
infra/nginx/nginx.conf + managed current.conf (edited via GUI/raw + apply).
Protected contract (engine-agent verifyProtectedContract) REQUIRES:
  pid /tmp/nginx.pid, access_log containers_json, listen 8080/8081,
  location /api/, location = /status, stub_status,
  proxy_pass containers_api + containers_web,
  upstream containers_api/containers_web with server api:3001 / web:3000,
  map $remote_addr $containers_client_ip,
  limit_req_zone api 300r/m + auth 5r/m + status 429,
  limit_req zone usage in /api/ (burst<=1000) and auth location (burst<=100),
  CSP / X-Content-Type-Options / X-Frame-Options headers on panel block.
  Nested-location rate-limit smuggling is rejected (top-level directives only).
  Applies to BOTH panel.containers.local and api.containers.local server blocks.

Every proxy location sets `X-Real-IP $remote_addr` (spoof-proof) and forwards
X-Forwarded-For. Route blocks (user proxy routes) also set X-Real-IP.
Rate zones key on $containers_client_ip = $remote_addr (never client headers).

Auth location uses regex `location ~ ^/api/auth/sign-in/email/?$` to defeat
trailing-slash bypass.

9. SECURITY MODEL & GUARDS
================================================================================
External attack surface: only nginx 127.0.0.1:8080 (login). All mutation is
behind session auth + role + recent-auth. No anonymous mutation.

SSRF defenses:
  - Webhook delivery: https-only, dotted hostname, DNS lookup(all,verbatim) →
    reject if ANY resolved address is private/loopback/ULA/link-local/
    6to4/Teredo/::ffff-mapped; public IPv6 allowed; redirect:manual.
  - Image pull / container create image: host extracted → DNS resolve-all →
    reject private; blocklist rejects internal hostnames + IPv4 shorthand +
    IPv6 special prefixes at schema level.
  - probeContainer: target restricted to non-management Docker-network
    containers by name (no arbitrary host).

Filesystem/archive:
  - Artifact inspect rejects path traversal (`..`, `\`, NUL), enforces
    entry/expansion/compression-ratio limits, OCI digest verification.
  - loadImage confines to realpath(artifactRoot/ready) — symlink-safe.
  - Upload paths are server-generated UUIDs; chunks sequential + digest-checked.

Orphan hygiene (15-min GC): cleanupExpiredSessions removes expired session
.part files, unreferenced ready/*.archive and quarantine/*.part (double DB
re-check before delete to avoid finalize race).

Backup restore: manifest digest+size verified; control snapshot integrity_check
+ FK check (inside txn before COMMIT) + table/column schema match; pre-restore
recovery snapshot + compensating rollback. Preserved on restore (security
invariants): auth tables, api_key, deployment_secret, notification_destination,
operation_job(+event), upload_session/chunk, artifact, audit_log.

Management-plane: control/ingress/probe/host networks and the 9 protected
volumes cannot be used by user-created containers or deployment manifests.
registry-credentials volume is mounted ONLY into engine-agent.

Secrets: AES-256-GCM at rest (deployment secrets, notification webhooks,
registry credentials) with per-service master keys; api keys SHA-256; internal
HMAC per-link. All files 0600, auto-generated, no committed .env.

10. DEPLOYMENT PIPELINE
================================================================================
1. Upload artifact (chunked, digest-verified) → /artifacts/:id/load
   (durable job) → image available.
2. Create deployment_manifest: imageDigest, command, entrypoint, env keys,
   secrets (by reference), volumes, port, protocol, healthcheck, route,
   rollout params. protectedNetworks/hostnames rejected.
3. Release (deploy.release job): engine-agent creates container on `probe`
   network → healthcheck probe → connect manifest.network + disconnect probe →
   nginx route upsert → observe → mark healthy. Old container stopped.
4. Rollback: connect previous release, switch route, verify, disconnect.
   Failed/interrupted releases are disconnected from probe/control and stopped.


================================================================================
11. BACKUP & RESTORE
================================================================================
Backup = control.sqlite snapshot + traffic.sqlite snapshot + manifest.json
(createdAt, digests, sizes). Scheduled via backup_schedule (interval, 24h
default, retention 7). Restore is OWNER + recent-auth + UUID confirmation,
runs under maintenance mode with pre-restore recovery snapshot and automatic
rollback on failure. See docs/BACKUP-RESTORE.md.

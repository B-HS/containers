# 0045 — 최근 인증(recent auth) 제거

2026-08-20. 사용자 결정: "로그인 한거면 그냥 로그인한거지" — 로그인 세션이면 즉시 인가한다.

## 배경

기존 `requireRecentRole` 은 재인증 절차(sudo 모드) 없이 **세션 생성 시각이 15분을 넘으면 무조건 거부**하는 구조였다. 파괴적 작업 전 재확인이라는 의도였지만 실제로는 로그인 15분 뒤 모든 관리 작업이 막히고, 푸는 방법이 재로그인뿐이었다. step-up 재인증 UI 가 없는 상태에서 세션 나이만 검사하는 것은 보안 이득 없이 UX 만 깨뜨린다.

## 결정

- `requireRecentRole`·`RECENT_AUTH_REQUIRED` 를 제거하고 모든 라우트를 `requireRole`(로그인 세션 + role 검사)로 통일한다.
- 파괴적 작업의 방어선은 role 게이트·확인 문구(confirmation)·audit 기록·API 키 scope 로 유지한다.
- 향후 step-up 재인증이 필요해지면 비밀번호 재입력 같은 **실제 재인증 플로우**와 함께 도입한다. 세션 나이 검사 단독으로는 되돌리지 않는다.

## 파생

- [0044](./0044-api-key-parity-and-egress-broker.md) 의 "recent 요구는 키 경로에서 scope 보유로 대체" 서술은 이 결정으로 한 단계 더 나아가 **세션 경로에서도 recent 요구 자체가 사라졌다**.
- 웹의 "15분 이내 로그인 필요" 안내 문구를 제거했다.
